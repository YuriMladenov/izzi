# Replay поправки след v3.4.2

Този пакет включва поправката за MP4 resolver tuple резултата и последващите replay поправки. Capture кодът, archive и state не се променят.

## Промени

- Премахване на невалидни статични media `src` (`#`, lesson HTML) преди браузърът да парсне елементите. Media shim-ът се регистрира в началото на документа и изчаква завършване на парсването, преди да зададе липсващи sources.
- Наблюдение и на динамични `src` промени. Валидните sources се запазват. MP4 не се задава на скрит audio player. Използват се lesson-scoped block IDs, когато са налични; не се използва media от друг block, ако има block metadata.
- При шрифтове се игнорират липсващи blobs, origin error records и bodies без разпознаваем font header. При картинки се игнорират липсващи blobs, празни bodies и HTML error bodies. Годен архивиран вариант на същия canonical path може да се използва през IZZI host alias.
- Реален архивиран origin 404 се обслужва като 404, когато няма годен ресурс. Не се фабрикуват картинки или шрифтове и не се правят upstream заявки.
- Познатите YouTube API/widget loader URLs се пренасочват към локален празен script; не се симулира работещ YouTube player. Познатите embed URLs получават локално съобщение за недостъпна външна медия.

## Windows проверка

1. Разопаковайте в нова папка и копирайте съществуващите `archive` и `state` до `server.py`. Запазете оригиналните папки като резервно копие. Спрете стария server.
2. Изпълнете `validate_replay.bat`: очакван резултат `22 passed, 0 failed`. Тестът използва временни synthetic bodies; не валидира конкретния личен архив.
3. Стартирайте `start_library.bat`, презаредете урока с Ctrl+Shift+R и проверете картинки, шрифтове, видео, seek и друг урок при изключен интернет.
4. Ако примерната картинка не се зарежда, изпълнете `asset_diagnostic.bat`. За друга картинка: `py tools\asset_diagnostic.py "/__host__/api.izzi.digital/път/до/картинка.png"`.
5. За IBM Plex Sans изпълнете `font_diagnostic.bat`.

Диагностиката чете само локални данни и не показва credential values. `UNRESOLVED` означава, че няма намерен годен body; прегледайте status/body/blob информацията. Споделете изхода, а не целите archive/state/HAR. Не стартирайте нов capture преди тази проверка.

## Проверки и ограничения

В облачната среда: 22 HTTP проверки, 10 HTML/runtime теста (един използва Node.js), съществуващият media-map contract test — успешни. Проверка с Chromium беше опитана, но browser процесът изтече по timeout преди да достигне локалния test server; browser rendering не е потвърдено за тези последващи промени. По-ранната MP4 поправка е потвърдена от потребителя на Windows, включително video/seek/navigation с изключен интернет.

Личният archive/state не е предоставен. Наличието и валидността на реалните IBM Plex Sans bodies и примерната PNG остават за локална проверка. Source-map 404 и legacy/vendor CSS предупреждения не блокират replay и не са поправяни чрез пренаписване на оригиналния vendor CSS.
